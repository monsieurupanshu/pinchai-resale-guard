# SHAP Analysis

Gain-based feature importance (see `docs/01_model_eval.md`) tells you
*what* mattered on average across all tree splits. It doesn't tell you
*how* — whether a high value pushes toward reseller or toward legit, or
whether that direction is even consistent. SHAP (Shapley values, via
`shap.TreeExplainer` — exact, not approximated, for tree models) answers
that, per-feature and per-prediction.

Generated by `src/model/shap_analysis.py`.

## Global Summary

![SHAP Summary](images/shap_summary.png)

Each dot is one test-set customer. Position = SHAP value (how much that
feature pushed this customer's score up or down). Color = the feature's
actual value for that customer (red = high, blue = low).

**Confirms the gain-based ranking's top signals, with clean directionality:**
- `pct_orders_discount_window`: low (blue) cleanly pushes toward legit,
  high (red) cleanly pushes toward reseller — the strongest, cleanest
  signal in the model.
- `shared_address_count`: same clean separation, confirming the network
  signal is directionally sound, not just present in the aggregate.

**Re-ranks some features relative to gain-based importance:**
`total_spend` and `total_quantity` rank much higher here than in the
gain-based chart. This is expected, not a contradiction: gain measures
how much a feature reduced training error when trees split on it; SHAP
measures actual output impact averaged across every real prediction. A
feature can be split on rarely (low gain) but still swing individual
outcomes meaningfully when it does apply (higher mean |SHAP|). These are
genuinely different questions.

## A Real Interaction Effect — Not Smoothed Over

`max_qty_single_order` shows something the gain-based chart couldn't
reveal: its color pattern is **inverted** relative to every other
feature. The leftmost (most negative SHAP, pushing toward legit) points
are colored red (high feature value) — the opposite of what every other
feature shows.

This was checked against the raw data, not just eyeballed from the plot:

| segment | mean max_qty_single_order | max |
|---|---|---|
| solo_reseller | 12.98 | 20.0 |
| loyal_bulk | 6.04 | 8.0 |
| stealth_reseller | 4.81 | 5.0 |
| ring_reseller | 2.70 | 5.0 |
| normal | 1.23 | 2.0 |
| shared_address_legit | 1.18 | 2.0 |

`loyal_bulk` — a legitimate segment — has the **second-highest**
`max_qty_single_order` of any segment, higher than both `ring_reseller`
and `stealth_reseller`. A single large order is not, on its own, a
reliable reseller signal: it's ambiguous between "aggressive reseller"
and "genuine bulk-buying loyal customer." The model has learned to net
this feature against other context (timing, account age, SKU diversity)
rather than treating it as a standalone red flag — which is why its
SHAP effect is conditional, not monotonic.

**Why this matters:** this is a materially more sophisticated finding
than "feature X is important." It shows the model learned a real,
non-linear interaction — exactly the kind of pattern a purely linear
model (see the Logistic Regression comparison in
`docs/04_model_comparison.md`) would struggle to capture cleanly, and a
genuine point of evidence for why a tree-based model earns its added
complexity here.
